# 把研究变成读者能看懂的报告

维护者：Hao Wu · 状态：active · 更新：2026-10-22

## 交付合同

文字报告本身要深入浅出、强结构化，多用bullet points、对比表与有意义的图表。HTML在此基础上把大段解释改成**结论型subtitle＋默认折叠详情**。这不是“有时间再美化”，也不是只换配色；两份产物分别验收。

生成前用几条内部笔记确定：读者看完应理解的三个判断、每个判断的证据、主线与细节的分界、最适合的图／表。已有研究足以完成这些，不为视觉设计再向运营发问卷。

## 内容怎么分层

| 层次 | 默认呈现 | 适合内容 |
|---|---|---|
| 一眼看懂 | 标题、subtitle、2–4条短要点 | 判断、对业务的含义、成立条件 |
| 直接比较 | 同规格对照表、价格区间图、问题→证据→改进关系 | 支撑判断的核心证据 |
| 按需理解 | 有信息量的subtitle／summary＋默认关闭details | 具体推理、逐款条件、补充例子 |
| 追溯 | 文末附录，HTML默认关闭 | 完整商品清单、父体ID、采集细节、异常字段、更新记录 |

只保留改变判断的限制在主线，贴着对应图表用一句话说明。不要每段都重复“样本不足、非销量、未验证”，也不能把影响结论的反例藏到附录。

长段不是按字符机械截断。先提炼一条读者应记住的结论，把并列事实拆成bullet，把跨对象事实移到同一比较表，推理过程移到详情。不要把每个原段落变成一张新卡片或一个空泛“更多详情”。

## 文字报告的具体做法

- 首页用一句判断＋3条摘要回答机会、竞争、下一步；元信息压缩为一行，不能先让读者读采集过程。
- 每章先给结论型小标题，例如“两个规格都有购买活动，价格竞争不同”，而非只有“数据分析”。
- 价格、规格、购买信号和竞争含义放在同一张可扫描的小表，不把多款数字塞进一段话。
- 同一论点用短bullet说明“证据是什么／意味着什么”，必要推理可保留一小段；不要连续多段叙述才给结论。
- 需求／定价有可比数据时，用区间或条形图呈现；用户问题用定性关系图或问题→证据→行动表。没有可靠比例时不造占比图，改用不带虚假数量的流程或证据矩阵。
- 核心竞品只选能说明竞争格局的代表项；全量SKU表进入附录。表头写业务含义，ASIN与父体原始ID不占主线大列。

## HTML的具体做法

默认使用包内 [结构化内容模型](report-schema.md) 和 `scripts/render_report.py`。它要求作者先完成信息取舍，而不是将Markdown逐段套`<p>`。先运行虚构示例查看版式，再填当前研究内容；示例数字不得流入真实报告。

```bash
python3 <skill-dir>/scripts/render_report.py <skill-dir>/assets/example-report.json --output example.html
python3 <skill-dir>/scripts/render_report.py report-content.json --output report.html
```

实际命令参数以脚本`--help`为准。用户另有视觉参考时可以调整组件样式，但须保留内容分层、默认可见证据和阅读验收；不能退化成通篇段落卡片。模板不是自动完成内容编辑的替代品。

- 每节的headline/subtitle直接说清观点，key points简短；解释放有明确标题的details，默认关闭。
- 数字关系由range图／比较表表达，候选方向由少量对照卡表达，用户问题由证据链表达；颜色和大数字不算图表。
- 完整样本放附录。不能先用多段写完所有商品，再在下面默认展开重复的几十张商品卡。
- 比较表在窄屏保持字段标签和可比关系：同规格核心对手优先使用“字段｜对手A｜对手B”的紧凑矩阵，分规格呈现（comparison块使用`mobile_layout: "compact"`）；逐问题卡适合问题分析，不用于替代竞品横向对比。不要靠无限长卡或横向拖动掩盖信息设计问题。
- 不默认加下载、打印、全局展开、筛选器等控件；每个控件都应有阅读用途。

## 有助理解时，主动配插图

不要只做纯文字与数据表。按内容选用产品实拍、使用场景示意、结构拆解、问题局部对比或操作流程插图；优先把抽象的使用问题画清楚。数量由信息需要决定，不为凑图稀释报告。

- 产品外观／结构：优先用户提供或有权使用的商品图片，绑定准确商品与变体，附来源；不要用错误尺寸的实拍替代当前变体。
- 场景／原理：没有合适实拍时可生成中性示意图，标明“示意图，非产品实测”；图片不能暗示已有测试结果、性能提升比例或不存在的功能。
- 数量／关系：统计仍用可追溯数据图，不能用AI图片生成柱高、价格或评分。
- 两版都在相关观点旁放图，配一句“这张图帮助理解什么”的caption和替代文本。HTML内联图片以保持离线阅读，手机保持比例和细节可辨。
- 资产保存到当前案例目录，原始产品图、生成图和真实客户案例不进入公开Skill仓库；公开示例用明确标注的虚构素材。

渲染器提供illustration块，按schema填本地图片、alt、caption和来源。没有可用图像工具或可靠素材时使用清楚的关系图／表，并诚实标注，不把不相关图库照当证据。

## 阅读验收：回答问题，不只是“页面正常”

作者先检查两份产物，再由可用的独立Agent拿真实产物验证。审核记录分为**内容理解**和**交互可用**，分别给证据；一项通过不能代替另一项。

1. **30秒读首页：** 能说出核心判断、一个理由和影响判断的限制吗？不能靠读完整报告才能理解。
2. **比较两个同规格竞品：** 能在同一表／图中找到价格、购买信号、评分积累与区别吗？不能偷换成“同品牌两种尺寸”或“全部字段存在”。
3. **看需求与问题：** 图表是否帮助比较？场景或结构难懂时是否有对应插图，且标清实拍来源或示意性质？用户问题能否连到具体产品动作？不可靠计数是否已改成定性表达？
4. **看完整章节：** 各节是否由subtitle和短要点支撑、长解释默认折叠？不能只看首屏截图。
5. **手机实际阅读：** 320–390px下比较表、图、详情都可理解；关键限定可见，完整清单没有淹没主线。
6. **操作回归：** 点击导航、Back/Forward、深链接、键盘开合；标题不被吸顶遮挡。检查桌面和手机的需求、竞争、用户问题三个实际章节截图。

以下属于需要返工的问题：正文主要仍是段落数组；比较数字分散在长句；有可比数据却没有任何有用图／表；长解释默认全展开；全量商品卡重复正文；审核只凭无横溢和按钮可用宣称可读。缺浏览器时标明未实测，保留候选状态，不能伪称阅读验收完成。
